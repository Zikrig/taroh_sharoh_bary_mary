# Контроль качества генераций

## A. До вызова модели

- [ ] Выбран известный `product`.
- [ ] Входные дата, время и место прошли нормализацию.
- [ ] Отмечено, является ли время приблизительным.
- [ ] Карта рассчитана астрологическим модулем.
- [ ] В payload нет секретов и платёжных данных.
- [ ] Сформирован ограниченный `fact_catalog`.
- [ ] Для совместимости присутствуют обе карты и синастрические факты.

## B. После построения профиля

- [ ] У каждого вывода есть хотя бы один `fact_id`.
- [ ] `fact_id` существует в каталоге фактов.
- [ ] Профиль содержит сильные стороны и возможные сложности.
- [ ] Есть хотя бы одно внутреннее противоречие, если оно подтверждено картой.
- [ ] Отношения, деньги и карьера не добавлены в продукт, где их нет.
- [ ] При приблизительном времени не сделаны уверенные выводы по домам и ASC.

## C. После написания текста

- [ ] JSON синтаксически корректен.
- [ ] Разделы идут в нужном порядке и не повторяются.
- [ ] Объём находится в диапазоне продукта.
- [ ] Текст написан на русском и обращается к пользователю единообразно.
- [ ] Есть конкретные жизненные проявления, а не только список качеств.
- [ ] Сильные стороны не превращают пользователя в идеального.
- [ ] Нет диагнозов, медицинских назначений и юридических советов.
- [ ] Нет обещаний дохода, брака, расставания или конкретных событий.
- [ ] Нет инвестиционных рекомендаций.
- [ ] Нет фраз, создающих зависимость от сервиса.

## D. При повторной попытке

1. Сохранить код ошибки и номер попытки.
2. Повторить только проблемный этап.
3. Передать модели краткий список нарушений, а не весь лог.
4. После второй неудачи остановить выдачу непроверенного результата.
5. Сохранить результат в статусе `failed` или `review_required`.

## E. Набор тестовых карт

Минимальный regression-набор должен включать:

- точное время рождения;
- неизвестное или приблизительное время;
- отсутствие партнёра;
- две карты с гармоничными связями;
- две карты с напряжёнными связями;
- пустой или неполный ответ модели;
- ответ с выдуманным `fact_id`;
- ответ с категоричными и запрещёнными формулировками.

Для каждого кейса проверять не красоту текста, а корректность контракта,
безопасность и отсутствие неподтверждённых фактов.
